# 🐙 Git & Version Control Best Practices for Firmware

> Clean repository management, avoiding binary bloat, branching strategies, and PR reviews.

---

## 1. The Strict Firmware `.gitignore`

Binary files (`.hex`, `.bin`, `.elf`, `.o`, `.d`) must **never** be committed to Git. They bloat the repository history, cause merge conflicts on every commit, and can easily be regenerated by running `make`:

```gitignore
# Compiled binaries & objects
*.o
*.elf
*.bin
*.hex
*.map
*.d

# Build output directories
build/
bin/
Debug/
Release/

# IDE workspace caches
.vscode/
.idea/
*.mxproject
```

---

## 2. Git Feature Workflow for Embedded Teams

1. **Keep `main` Green:** `main` should always compile cleanly without warnings.
2. **Branch per Feature:**
   ```bash
   git checkout -b feature/i2c-bmp280-driver
   ```
3. **Write Atomic Commits:**
   - Bad: `git commit -m "fixed stuff and added some sensor code"`
   - Good: `feat(drivers): add BMP280 temperature compensation formulas`
4. **Rebase Before Merging:**
   ```bash
   git checkout feature/i2c-bmp280-driver
   git fetch origin
   git rebase origin/main
   ```
