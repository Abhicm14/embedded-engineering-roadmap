# 🔨 The C Build Process for Embedded Targets

> Preprocessing, compiling, assembling, linking, and analyzing linker map files.

---

## 1. The 4 Stages of Compilation

```
source.c + headers.h
        │
        ▼ (Stage 1: Preprocessor - gcc -E)
source.i (Expanded macros, included headers, stripped comments)
        │
        ▼ (Stage 2: Compiler - gcc -S)
source.s (Target architecture Assembly code - ARM Thumb-2)
        │
        ▼ (Stage 3: Assembler - as)
source.o (Relocatable object file with symbol tables)
        │
        ▼ (Stage 4: Linker - ld with linker.ld)
firmware.elf (Absolute memory addresses, combined sections)
        │
        ├─────────────────────────────┬─────────────────────────────┐
        ▼                             ▼                             ▼
firmware.bin (Raw binary)      firmware.hex (Intel HEX)      firmware.map (Memory Map)
```

---

## 2. Analyzing the Linker Map File (`.map`)

The map file generated by the GNU Linker (`-Wl,-Map=firmware.map`) is the most important diagnostic file for firmware sizing:

```
.text           0x08000000     0x1240 build/startup.o
                0x08000000                g_pfnVectors
                0x08000040                Reset_Handler
.text           0x080000a0      0x380 build/main.o
                0x080000a0                main
.data           0x20000000       0x20 load address 0x080015c0
                0x20000000                s_sensor_config
.bss            0x20000020      0x100 build/main.o
                0x20000020                s_rx_buffer
```

### Key Diagnostic Checks:
1. **Flash Consumption:** Total Size = `.text` + `.rodata` + `.data`
2. **RAM Consumption:** Total Size = `.data` + `.bss` + Minimum Stack + Heap
3. **Unexpected Bloat:** If `printf` or `sprintf` is included inadvertently, you will see `libc.a` pull in 20KB+ of Flash into `.text`!
